# App developer: one API for automatic RF reports

**Phone/company-code Android app:** use the [mobile upload contract](rf-mobile-upload.md). It adds administrator-provisioned installation bearer credentials to this same upload endpoint without requiring portal login on the phone. The cookie/CSRF flow below continues to apply to portal-authenticated callers only.

Updated 28 October 2026. Deploy this backend release before using the new route.

After the drive ends, finish writing its final ZIP and call this API once using the existing logged-in user's session:

```http
POST https://s-traccceer.vinfocom.co.in/api/rf-logs/upload
Content-Type: multipart/form-data; boundary=<generated by the HTTP client>
X-CSRF-TOKEN: <matching st.csrf cookie, when required>
```

Use the deployed backend origin `https://s-traccceer.vinfocom.co.in`. The request examples use this same origin. Install the updated backend release and its server-side RF storage configuration before testing the new endpoint.

Send form-data fields:

| Field | Type | Required | Example |
| --- | --- | --- | --- |
| `file` | File | Yes | Final `drive-test.zip` binary |
| `uploadId` | Text UUID | Yes | `7d8d4442-21b3-4a60-a3dc-b7b96c9f062c` |
| `sessionId` | Text integer | Yes | Actual existing session ID, e.g. `4266` |
| `subSessionId` | Text | No | `20` |
| `projectId` | Text integer | No | Actual company project ID |

Let the HTTP client generate the multipart Content-Type/boundary. The filename and exact size are taken from the file; no separate fileName/fileSizeBytes JSON is required. Preserve all existing login cookies and send the required CSRF header. Company, user and IN/TW DB come from the authenticated login; omit companyId, userId and destination email in the normal app flow.

The backend registers the upload, stores/verifies the ZIP privately in S3, records completion and queues the existing PDF/email pipeline. The app does not need separate registration, S3 PUT, `/complete`, PDF-generation or email-send requests for this single-call flow. Existing login is still required.

The response is the existing event JSON (200). Example excerpt:

```json
{
  "uploadId":"7d8d4442-21b3-4a60-a3dc-b7b96c9f062c",
  "eventKey":"IN:7d8d4442-21b3-4a60-a3dc-b7b96c9f062c",
  "region":"IN",
  "uploadStatus":"completed",
  "reportStatus":"ready",
  "sessionId":4266,
  "error":null
}
```

PDF generation/email delivery run asynchronously after acceptance; this response is not confirmation that the email reached an inbox. The backend sends the generated PDF attachment to the valid registered company email (`tbl_company.email`) and any eligible optional additional recipients. No S3 or SMTP credentials belong in the app.

Generate one UUID per final ZIP and persist it across retries/restarts. Retry with the same UUID, original filename, size and metadata. Once accepted, a repeat call returns the existing event without uploading another ZIP or queuing another report. Different metadata under an existing UUID returns 409. A storage failure leaves the upload pending for retry. Do not mutate a ZIP under the same UUID.

The single-call request passes through the backend, so existing `Security:MaxUploadBytes`, multipart/server/IIS/proxy limits apply, including multipart overhead; the code default HTTP cap is 100 MiB, with configuration allowed up to 500 MiB. `RfLogIntegration:MaxZipBytes` also applies. Use suitable upload timeouts. The optional direct-to-S3 flow remains available for larger uploads and does not require changing existing consumers.

Useful errors: 400 invalid metadata/ZIP/CSRF; 401 login required; 403 wrong session/company; 409 metadata conflict; 413 configured size limit; 500/503 retryable service/storage failure. Some multipart validation limits may return 400 or be rejected upstream before the app.

Keep the supported NetworkLog CSV in the ZIP. Preserve optional L3/Event and `WiFi_plot.csv` companions. A Wi-Fi-only ZIP is not a newly supported PDF format.

Optional progress/download APIs remain available as documented in `rf-app-developer-handoff.md`; they are not required to trigger report/email generation.
